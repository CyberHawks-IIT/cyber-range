Essential Notes

  • Every finding above is reachable straight from user, computer, or an unauthenticated/any-domain-user starting point. You never need to solve one finding to unlock a different one.
  • The pool of ~1000 user accounts is mostly decoys, and the usernames themselves aren't a secret — they're drawn straight from a public statistically-likely-usernames list, so username enumeration/spraying tools will find real accounts easily. The passwords are what's actually protected: real targets are marked "pool account — enumerate" above and have to be found (LDAP, SMB, etc.), not guessed.
  • The literal password password belongs only to user and computer — it will not unlock anything else.
  • Machine account quota is unchanged (10), so you can join your own computer account instead of using computer if you'd rather keep it clean.
  • Keep testing scoped to the 7 AD hosts and the 10.0.2.10 attacker box (both on 10.0.2.0/24), plus the standalone 10.1.1.1 service-abuse host.
  • If something breaks badly — locked account, corrupted AD object, crashed VM — ask course staff for a snapshot rollback rather than trying to repair it yourself.
